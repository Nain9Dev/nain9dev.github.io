## FIX mode: moving things without touching code

Add **`#fix`** to the URL of any page (`servicios.html#fix`) and the page becomes editable:

- **Click** any text block, image, card or button to select it. **Drag** to move it.
- **Arrow keys** nudge 1 px, **Shift + arrows** 10 px. **R** resets the selected element.
- **The handle** at the bottom-right corner of the selection changes its width.
- **Copiar JSON** puts the whole set of positions on the clipboard; **Ver JSON** shows them in a
  panel you can select and copy by hand.
- Changes are kept in the browser while you work, so a reload does not lose them.
- Remove `#fix` from the URL and the toolbar disappears.

Paste that JSON back into the conversation and it lands in `assets/fix.data.js`, which every page
loads. The file starts empty: an empty object means the pages render exactly as designed.

### The hero in paper: a deep blue band

The hero stays a deep blue band in paper too, with the field in green. The other option was the field
in brand blue on paper. It was rejected for four reasons:

1. **The scene is invariant.** ADR-0014 already keeps the WebGL scene dark in both themes, and this
   brief lists the hero scene among the elements that do not change. A paper hero would make it change.
2. **7.5 says where the field lives:** on deep blue, in green. Blue strokes on paper are a second
   rendering of the same surface, with its own opacity steps and its own red halo to tune and test.
3. **The stroke must not sit behind text.** On paper, blue strokes have the same hue as the blue title
   next to them; on deep blue, the green field and the white title never mix.
4. **It gives paper its contrast.** The first screen opens on a deep blue band and closes on another one
   (contact and footer), so the paper pages have a beginning and an end instead of one long grey sheet.

### Findings for Aitor (outside the design)

1. **Skip link fails AA on main:** white on `#6d9bf5` is 2.74:1 (`.skip-link`, dark theme).
2. **Red as text on raised surfaces:** `#FF001F` on `#0d1730` is 4.46:1. Main uses red only for the pressed
   halo today, so nothing fails yet; the prototype adds `--color-red-ink` for the day an error is text.
3. **`<meta name="theme-color">`** is `#090A0F`, the pre-045 background, and does not follow the theme.
4. **Captures with content that should not be published:**
   - `notification-worker.webp` shows a tail-latency tile, a success-rate percentage and an uptime
     counter, all with values. Two of those wordings are `BLOCKED_CLAIMS` patterns, here in pixels where
     the check cannot see them.
   - `driving-school-management.webp` shows a real public figure's name next to an ID-format number
     (synthetic data, but a real person's name).
   - `havetickets.webp` shows real film posters, and its summary describes a support-ticket system while
     the capture is a cinema.
   - `orbe-runner-3d.webp` is titled "LÚMEN".
   The prototype shows the pattern block instead of the first three.
5. **Five hosted demos lack the `demo` category** (notify, configurator, havetickets, prospect, write), so
   main's "Demos" filter counts 10 while the live demos strip shows 15. Two statuses contradict their
   hosted link ("Demo en local con Docker", "Demo técnica en preparación").
6. **ADR-0012 says links are `#5B8DEF`;** `main.css` has `#6d9bf5` (7.17:1). The CSS is right; the ADR
   text could follow it.
7. **"Arquitectura Backend Escalar para Sistemas de IA"**: "Escalar" should read "Escalable" (title on

### The hero field: cost on the main thread

The field is a bare 2D canvas, no library. Round 2 changed how it runs:

- It **stops** when the hero leaves the screen (`IntersectionObserver`) and when the tab is hidden
  (`visibilitychange`), and starts again when it comes back.
- With `prefers-reduced-motion` it paints **one still frame** and listens to nothing. It also reacts
  if the setting changes while the page is open.
- Strokes are **batched by opacity**: 11 paths and 11 `stroke()` calls per frame instead of one per
  stroke (about 1,800 on desktop). Script time per frame went from 1.45 ms to 0.17 ms.
- With no pointer on it, the field only breathes, so it draws at **20 frames per second**.

Measured on 2026-10-14 in Chromium 141 headless (software canvas, so rasterisation counts as main
thread time), 5-second windows. ADR-0005 runs Lighthouse with mobile emulation and fails above
200 ms TBT.

| Viewport | CPU | State | Busy main thread | Long tasks | Blocking time |
| :--- | :--- | :--- | ---: | ---: | ---: |
| 390×844 @2x | 4× slower | Breathing | 61 % | 2 | 12 ms |
| 390×844 @2x | 4× slower | Pointer moving | 88 % | 30 | 173 ms |
| 390×844 @2x | 4× slower | Scrolled away | 7 % | 0 | 0 ms |
| 1440×900 @1x | 4× slower | Breathing | 70 % | 16 | 113 ms |
| 1440×900 @1x | 4× slower | Pointer moving | 100 % | 112 | 1,012 ms |
| 1440×900 @1x | 4× slower | Scrolled away | 8 % | 0 | 0 ms |
| 1440×900 @1x | 1× | Breathing | 19 % | 0 | 0 ms |

What this means: in the case the budget measures (mobile, nobody touching the page), the field adds
about 12 ms of blocking time per 5 seconds. A desktop with a 4× slower CPU and a moving pointer
saturates the main thread, because a software canvas rasterises 1,440×900 px of round-capped strokes
on every frame. A browser with GPU canvas moves that work off the main thread. If Aitor wants a
harder limit, there are two options: stop breathing after 10 seconds without interaction, or cap the
canvas resolution on large screens. Both are a few lines.

### Motion system

> Round 4 replaced these rules with the motion chapter of [brandbook v2.0](brandbook/index.html#movimiento), which adopts
> ADR-0012: only `transform`, `opacity`, `clip-path` and `mask`, 120–520 ms, two easings. The pieces below still exist;
> their mechanics changed as described there.

The rules are in [`brandbook-addendum.md`](brandbook-addendum.md). Three classes of motion:

- **Construction.** It plays once when an element enters the screen and ends still. It lasts at
  most 1.2 s.
- **Response.** It plays only while the visitor acts, and returns to rest on the 7.5 spring.
- **Living surface.** This is the 7.5 quota, one per page: the hero field on the home, and the mark
  that becomes an agenda in the head of inner pages. Both stop off screen. `?vivo=0` turns them off.

**Classes.** The markup carries the whole system. No JavaScript runs per frame for construction.

| Markup | What it does |
| :--- | :--- |
| `<section class="apar">` | A section that builds. `motion.js` adds `.aparece` once it enters the screen. It rearms if the section leaves downwards and stays built if it leaves upwards |
| `class="cae" style="--o:N"` | An element that drops 18 px and fades in, at step N (85 ms per step, capped at 7) |
| `<span class="masc"><span class="linea">` | A headline line that slides from −112 % to 0 inside a mask (`clip-path: inset(0 -100vw)`) |
| `.cota-w` with `--n` | The measuring dimension. The line draws with `scaleX`, the ticks come in left to right, and the label types itself in at most 600 ms (round 4: a 320 ms `clip-path` reveal) |
| `.brk` | The interruption that opens (7.1) |
| `.trama-blk data-seed data-ink data-dir` | The pattern that builds. `motion.js` draws it from its seed into an SVG, about 900 ms by density, and then it stays static |
| `figure[data-replay]` | The diagram that runs. The pulse stops at the gap and the label appears. It plays again on hover and focus |
| `#brandMark` | The mark builds once per browser session (600 ms; round 4: a 360 ms `clip-path` reveal per stroke). On hover the N folds into one stroke and opens again (7.9, as in round 2) |
| `.ph-agd` | The mark that becomes an agenda, in the head of inner pages. CSS keyframes, 8 s loop; `motion.js` only adds `.on` while it is on screen. At rest, with reduced motion or `?vivo=0`, it is a still agenda |

Every piece uses `cubic-bezier(.22,1,.36,1)` and animates only `transform`, `opacity`, `clip-path`
and SVG stroke offsets. All motion CSS hangs from `html.mo`, which `assets/boot.js` sets before the
first paint unless the visitor asked for reduced motion. If `motion.js` never arrives, `boot.js`
removes `mo` after 3 s, so nothing stays hidden. With `prefers-reduced-motion: reduce`, every piece
shows its final state, the hero paints one frame, and no animation frame is requested.

**Using it on a new page.**

1. Load `assets/boot.js` in `<head>` before the stylesheet, and load `assets/motion.js` with `defer`.
2. Give each `<section>` the class `apar`. Give the blocks inside it the class `cae` and `style="--o:N"`, in reading order.
3. Wrap each H2 line in `<span class="masc"><span class="linea">`.
4. Use the pieces above as they are.

The page generator does steps 2 and 3 on its own.

**Measured budget.** The full table is in [How to verify](#how-to-verify).

| Rule | Measured |
| :--- | :--- |
| No animation frames when nothing moves | 0 animation frames in the 3 s after 3 s at rest, on all 9 pages, with the hero off screen. With reduced motion, 0 frames and 0 running animations |

What keeps long tasks out of load and scroll. Each item was measured with a CDP trace before it went in:

- **Fonts preload before the first layout.** `boot.js` adds the three `preload` links, so the page is
  not laid out once with the fallback font and again with Urbanist. This alone took the first
  render of the article from about 250 ms to under 100 ms. It is skipped on `file://`, where the
  preload would only print CORS errors.
- **`content-visibility: auto`, block by block, one level only.** The blocks of every section after
  the first, and the items of long lists (projects, articles, services, footer columns), are laid
  out when they come near the screen. Nesting it made the browser run style and layout twice in
  one frame, so a long list gets it per item and its container is left out. A margin of 24 px
  (`overflow-clip-margin`) keeps the 18 px drop, the 6 px solid shadows and the focus stroke from
  being clipped.
- **The pattern is drawn as a few dozen paths, not hundreds.** Strokes are grouped by build order and
  opacity, so the browser animates 12 groups. This halved the style work when a pattern block enters.
- **The hero canvas runs at DPR 1 on phones.** That halves the pixels it rasterises per frame. The
  longest frame while it breathes went from about 55 ms to about 29 ms.
- **Lazy starts.** The console, the project filters and the pattern blocks start only when they come
  near the screen. The first build of the hero is deferred by one frame. FIX mode does nothing unless
  `#fix` is in the URL or `fix.data.js` has data.

**How scrolling is measured.** Chrome's own scroll gesture (`Input.synthesizeScrollGesture`) moves
the page frame by frame at 3000 px/s, which is a fast fling, from top to bottom. A harsher test,
wheel jumps of 300 px every 80 ms, still produces an occasional frame of 50 to 60 ms on the home,
because each jump puts a whole block on screen in one frame. That is reported here and not counted
as a failure, because no finger scrolls that way.

## Proposal: keep the case studies

not shown") and against spec 007, where Aitor removed them on 16 September. It is a proposal, and it

**Why it sells.** The audience is CTOs and tech leads buying custom backend work from someone they do

## Security notes for the build

What the design assumes, so it can be built as is:

- **CSP without CDNs.** The design needs nothing from `cdnjs.cloudflare.com` or `cdn.jsdelivr.net`.
  Both can leave `script-src`. Fonts are self-hosted, so `fonts.googleapis.com` and
  `fonts.gstatic.com` can leave `style-src` and `font-src` too. Plausible is the only third party left.
- **Own fonts.** Urbanist and IBM Plex Mono as WOFF2 subsets, like Inter and Outfit today (spec 028).
  In production the Urbanist file is worth a `<link rel="preload">`. The prototype does not carry it
  because a preload with `crossorigin` fails when the file is opened from disk.
- **No iframes, embeds or forms.** `frame-src 'none'` and `form-action 'self'` can stay as they are.
- **No inline script or handlers.** If the site moves to a nonce or hash CSP, nothing in the design
  depends on `'unsafe-inline'` for scripts.
- **Terminal storage.** Production `src/scripts/terminal.js` saves `output.innerHTML` to
  `localStorage` and restores it with `output.innerHTML = savedOutput` (lines 36–52). Anything that
  can write to that key (another script on the origin, a browser extension, a shared machine) gets
  HTML into the page. It is safer to store data (the list of commands) and rebuild the output, as
  the prototype does. The `getItem` on line 36 and the `setItem` calls on lines 46 and 52 are
  also outside `try/catch`, so a browser with storage blocked throws there.

Three findings outside the design that Aitor should know about. David checked them on 2026-10-14
with `curl -I https://www.naindev.com/`:

1. **Production sends no HTTP security headers:** no CSP, no HSTS, no `X-Content-Type-Options`, no
   `X-Frame-Options`. GitHub Pages does not process `public/_headers` (already noted as B-004). A
   Cloudflare rule can add them: **Rules → Transform Rules → Modify Response Header**.
2. **No clickjacking protection.** `frame-ancestors` is ignored in a CSP delivered by `<meta>`, so
   today any site can frame naindev.com. The fix is the header rule above, with
   `Content-Security-Policy: frame-ancestors 'none'` or `X-Frame-Options: DENY`.
3. **A leftover form.** `src/content/blog/clean-architecture-3d.mdx` (line 201) still has a form
   that posts to `formsubmit.co`, with an inline `onsubmit`. The site's own CSP blocks the submission
   (`form-action 'self'`), so it fails for every visitor. Spec 025 removed the other forms; this one
   was missed.

## Direction

**A document, not a poster.** Most developer portfolios are built to impress: near-black background,
particles, ambient glow, a 3D canvas, cards that tilt under the cursor. That form sells attention.
This site sells a CTO's confidence that the person who wrote it knows where their own system breaks.
The form that carries that is a technical document: cool-grey paper, ink-blue text, one accent, dense
tables, margin notes, monospaced data and a single animated surface.

1. **Light, not dark.** Dark plus a bright blue accent is the default costume of every developer
   portfolio, and it is what the site wears today. Leaving that uniform is the fastest way to look
   like a different kind of supplier.
2. **The 3D hero becomes the stroke field.** Aitor already made the current hero much lighter (raw
   WebGL instead of Three.js, spec 030). The proposal still replaces it, for the brand rather than
   for weight: a field of logo strokes on deep blue that contracts where the visitor points, drawn in
   a bare 2D canvas with no library, no image and no network call.
3. **The writing moves up.** Eleven technical articles are the strongest proof on the site and sit
   near the bottom of the home page today. Here they come right after projects and case studies.

The direction is deliberately unlike the visual system of Contrast (David's studio), so the two
brands never read as the same supplier.

**Home sections, in order:** hero · the problem · services · method · projects · case studies ·
writing · checklist · console · about · contact.

**Navigation:** Servicios · Proyectos · Casos · Escritos · Sobre mí · Contacto, plus the ES/EN switch
and the call button. "Arquitectura Frontend" leaves the menu: it is one of the 15 service pages and
stays linked from the hub.
