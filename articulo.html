Arquitectura backend para sistemas de validación 3D deterministas Backend architecture for deterministic 3D validation systems

Aitor Nain Mendoza Vallejo · .NET · 3D · [TEXT] fecha · lectura [TEXT] min Aitor Nain Mendoza Vallejo · .NET · 3D · [TEXT] date · [TEXT] min read

Un sistema que valida geometría tiene una obligación que no tienen casi los demás: dar siempre el mismo resultado para el mismo archivo. Esta es la arquitectura que lo sostiene, y las tres decisiones que la hacen posible. A system that validates geometry has an obligation almost no other has: to always give the same result for the same file. This is the architecture that holds it up, and the three decisions that make it possible.

El determinismo es una decisión de arquitecturaDeterminism is an architecture decision

Una validación no determinista es peor que no validar: da una seguridad que no existe. Si la misma malla pasa hoy y falla mañana, el equipo deja de creer en el semáforo y lo salta. El determinismo no se consigue con cuidado al programar, se consigue sacando del camino todo lo que puede cambiar: el orden de los hilos, la hora del sistema, la versión de una librería, la respuesta de un servicio externo. A non-deterministic validation is worse than no validation: it gives a confidence that does not exist. If the same mesh passes today and fails tomorrow, the team stops believing the light and walks past it. Determinism is not achieved by being careful while coding; it is achieved by taking everything that can change out of the path: thread order, system time, library versions, an external service's answer.

Tres capas y una fronteraThree layers and one boundary

El dominio contiene las reglas y no conoce ni la base de datos, ni la cola, ni el proveedor de IA. La capa de aplicación orquesta. La infraestructura es sustituible por definición. La frontera importante no está entre capas: está entre lo que tiene que ser reproducible y lo que no puede serlo. The domain holds the rules and knows nothing about the database, the queue or the AI vendor. The application layer orchestrates. Infrastructure is replaceable by definition. The important boundary is not between layers: it is between what must be reproducible and what cannot be.

La cifra que mandaThe figure that rules

El presupuesto de tiempo por activo es lo que decide la arquitectura: por debajo de un umbral, la validación va en línea; por encima, va a una cola y el resultado se consulta después. Es una decisión de producto disfrazada de detalle técnico. The time budget per asset is what decides the architecture: below a threshold, validation runs inline; above it, it goes to a queue and the result is polled later. It is a product decision disguised as a technical detail.
